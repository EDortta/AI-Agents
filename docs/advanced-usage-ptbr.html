Guia de referência

Detalhes avançados de uso

Como instalar, atualizar e configurar o AI-Agents sem perder conteúdo do projeto — e como a identidade local se relaciona com o AI-GovernanceKit.

Fluxo recomendado

# 1a. Instalação nova
bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.1.6/scripts/install-agents-kit.sh) \
  --target "$PWD"

# 1b. Atualização de uma instalação existente
bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.1.6/scripts/install-agents-kit.sh) \
  --target "$PWD" --upgrade

# 2. Configure a identidade desta máquina/checkout
governancekit configure

# 3. Preencha o contexto e os limites específicos do projeto
# .docs/software-overview.md → project_context_ready: yes
# .docs/limits.md            → limits_ready: yes

# 4. Valide tudo
governancekit doctor
governancekit --version

Não existe obrigação de criar WORKSPACE.md. A identidade executável da instância fica em .governancekit-identity.json. O nome do operador e a conta SMTP usados nos contratos ficam separadamente em .credentials/identity.json.

As duas identidades locais

ArquivoResponsabilidadeCriado porGit
.credentials/identity.jsonValores dos slots OPERATOR_NAME e SMTP_ACCOUNT nos contratos.install-agents-kit.shIgnorado; modo 0600.
.governancekit-identity.jsonIdentidade da máquina e do checkout: host, caminho, portas e propriedade de branches.governancekit configureIgnorado; modo 0600.

Parâmetros de install-agents-kit.sh

ParâmetroO que fazQuando usar
--target <dir>Define o projeto alvo. O padrão é o diretório atual.Sempre que o script for executado fora do projeto.
--repo <owner/repo>Seleciona outro repositório de origem.Forks e distribuições internas.
--ref <ref>Seleciona tag, branch ou commit. O padrão é v1.1.6.Fixar uma versão ou testar uma origem específica.
--checksum <sha256>Valida o tarball baixado e aborta se o hash divergir.CI e instalações com exigência de integridade.
--upgradeAtualiza arquivos do kit e preserva contexto, regras, identidade, handoff e issues do projeto.Atualização normal de uma instalação existente.
--forceSobrescreve arquivos existentes numa instalação. Não pode ser combinado com --upgrade.Somente quando a substituição integral foi revisada e é intencional.
--strictCom --upgrade, retorna erro quando algum arquivo protegido exige merge humano, mesmo preservando-o.Pipelines de CI.
--checkRelatório somente leitura do que seria substituído, preservado ou guardado.Antes de migrar uma instalação antiga.
--migrateExtrai identidade e separa conteúdo do projeto que foi escrito em arquivos do kit. Exige terminal e confirmação.Instalações antigas ou com AGENTS.md personalizado.
--dry-runCom --migrate, mostra o relatório sem escrever.Auditoria segura e automação.
--helpMostra a ajuda incorporada à versão executada.Confirmar parâmetros disponíveis.

--check não combina com modos de escrita; --dry-run só combina com --migrate; --strict só combina com --upgrade.

Instalação nova, atualização e migração

Nova

install-agents-kit.sh \
  --target /projeto

Cria os arquivos ausentes, pergunta a identidade do operador e deixa os gates de contexto como não prontos.

Atualização

install-agents-kit.sh \
  --target /projeto \
  --upgrade

Substitui somente o que pertence ao kit e reaplica a identidade local.

Legado

install-agents-kit.sh --target /projeto --check
install-agents-kit.sh --target /projeto --migrate
install-agents-kit.sh --target /projeto --upgrade

Separa primeiro o conteúdo misturado e só depois atualiza.

Parâmetros de identidade do GovernanceKit

governancekit configure \
  --operator-name "Nome" \
  --host-id "maquina-01" \
  --instance-path "/caminho/absoluto/projeto" \
  --sibling-path "/outro/checkout" \
  --assigned-ports "3000,8000" \
  --branch-ownership "feature/minha-branch"
ParâmetroObrigatórioSignificado
--operator-nameSimOperador humano desta instância.
--host-idSimIdentificador estável da máquina ou ambiente.
--instance-pathSimCaminho absoluto deste checkout.
--sibling-pathNãoOutro checkout que pode disputar branch ou recursos.
--assigned-portsNãoLista de portas reservadas por esta instância.
--branch-ownershipNãoBranches operadas por esta instância.
--set KEY=VALUENãoPreenche placeholders legados; pode ser repetido.

Sem parâmetros, governancekit configure pergunta interativamente. Com parâmetros, os três campos obrigatórios precisam ser fornecidos.

O que o upgrade preserva

Território do kitTerritório do projeto/instância
AGENTS.md, adaptadores de agentes, .docs/agents/, workflows, templates e páginas de referência..docs/software-overview.md, .docs/limits.md, docs/, handoff.md, identidades e issues.

Um AGENTS.md modificado é preservado e a nova versão fica em AGENTS.md.kit-new para merge manual.
