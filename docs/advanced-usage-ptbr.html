Guia de referência

Detalhes avançados de uso

Como instalar, atualizar e configurar o AI-Agents sem perder conteúdo do projeto — e como a identidade local se relaciona com o AI-GovernanceKit.

Fluxo recomendado

# 1. Instale o CLI GovernanceKit — é ele que instala e atualiza o kit AI-Agents,
#    baixando a release fixada (verificada por checksum)
pip install git+https://github.com/EDortta/AI-GovernanceKit.git

# 2a. Instalação nova
governancekit --root "$PWD" install-agents

# 2b. Atualização de uma instalação existente
governancekit --root "$PWD" install-agents --upgrade

# 3. Configure a identidade desta máquina/checkout
governancekit configure

# 4. Preencha o contexto e os limites específicos do projeto
# docs/software-overview.md → project_context_ready: yes
# docs/limits.md            → limits_ready: yes

# 5. Valide tudo
governancekit doctor
governancekit --version

Não existe obrigação de criar WORKSPACE.md. A identidade executável da instância fica em .governancekit-identity.json. Os valores do operador usados nos contratos ficam separadamente em .gk/operator.json.

As identidades locais

ArquivoResponsabilidadeCriado porGit
.gk/operator.jsonRespostas guardadas para o slot OPERATOR_NAME (e demais valores do operador); reaplicadas a cada upgrade.governancekit install-agentsIgnorado.
.governancekit-identity.jsonIdentidade da máquina e do checkout: host, caminho, portas e propriedade de branches.governancekit configureIgnorado; modo 0600.
.credentials/identity.jsonArquivo legado de valores de slot, escrito pelo instalador shell aposentado; o governancekit configure o lê como fonte legada do nome do operador — o install-agents não.instalações legadasIgnorado; modo 0600.

.gk/project-config.json não é identidade: guarda as respostas de configuração do projeto (entrevista de escopo). O doctor pode dar HINT quando ausente.

Instalação nova, atualização e migração

Nova

governancekit --root /projeto install-agents

Cria os arquivos ausentes, pergunta a identidade do operador e deixa os gates de contexto como não prontos.

Atualização

governancekit --root /projeto install-agents --upgrade

Substitui somente o que pertence ao kit e reaplica os valores guardados do operador. Um AGENTS.md editado à mão é preservado; a versão nova fica ao lado como AGENTS.md.kit-new.

Legado

governancekit --root /projeto install-agents \
  --upgrade --migrate-content

Extrai os contratos legados do projeto antes de atualizar; revise o que chega em docs/project-rules/.

Parâmetros de identidade do GovernanceKit

governancekit configure \
  --operator-name "Nome" \
  --host-id "maquina-01" \
  --instance-path "/caminho/absoluto/projeto" \
  --sibling-path "/outro/checkout" \
  --assigned-ports "3000,8000" \
  --branch-ownership "feature/minha-branch"
ParâmetroObrigatórioSignificado
--operator-nameSimOperador humano desta instância.
--host-idSimIdentificador estável da máquina ou ambiente.
--instance-pathSimCaminho absoluto deste checkout.
--sibling-pathNãoOutro checkout que pode disputar branch ou recursos.
--assigned-portsNãoLista de portas reservadas por esta instância.
--branch-ownershipNãoBranches operadas por esta instância.
--set KEY=VALUENãoPreenche placeholders legados; pode ser repetido.

Sem parâmetros, governancekit configure pergunta interativamente. Com parâmetros, os três campos obrigatórios precisam ser fornecidos.

O que o upgrade preserva

Território do kitTerritório do projeto/instância
AGENTS.md, adaptadores de agentes, .docs/agents/, workflows, templates e páginas de referência.docs/software-overview.md, docs/limits.md, docs/, handoff.md, identidades e issues.

Um AGENTS.md modificado é preservado e a nova versão fica em AGENTS.md.kit-new para merge manual.

Códigos de saída relevantes

0Operação concluída.
1A operação falhou — a mensagem nomeia o motivo (por exemplo, falha de download ou de checksum).
2Parâmetros incompatíveis ou inválidos, ou raiz de alvo inutilizável.

Um merge manual pendente (AGENTS.md.kit-new) ou um valor de operador não coletado é reportado na saída da execução mas ainda sai 0 — leia a saída (e rode governancekit doctor); não confie só no código de saída.

Próximos passos

Rodar o kit agendado, sem ninguém olhando, tem contrato próprio e modos de falha próprios — veja rodar sem supervisão. Para todos os comandos do CLI, seleção de contexto, diagnóstico e automação em CI, consulte os detalhes avançados do GovernanceKit.
