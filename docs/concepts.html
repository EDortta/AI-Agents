AI Agent Governance — core concepts

What governing AI agents means, why it matters, and how the tools in this ecosystem fit together — a plain-language guide for newcomers.

Fundamentals

What is AI agent governance?

AI agents like Claude, Copilot, and Cursor write code, make decisions, and execute actions inside your repository. They are powerful tools — and without clear rules, each agent interprets its work differently, with no log, no scope limits, and no predictability.

AI governance is the layer of contracts, limits, and records that ensures agents (and humans) follow the same processes. Instead of hoping the agent will "pick up" the rules from context, you make them explicit, enforceable, and auditable.

The result: AI-assisted work as predictable as a CI pipeline — where anyone (or any agent) joining the project knows exactly what they can do, what they can't, and how to document what they did.

Audience

Who is this for?

Governance is not only for large teams. It solves real problems at any scale.

🧑‍💻

Solo developer

You use several AI agents across different projects and want them all to follow the same conventions — without repeating instructions every time.

👥

Development team

Your team adopted AI, but each member configured their agent differently. Governance creates a shared contract that every agent follows.

🏢

Enterprise engineering

You need traceability, scope limits, and an audit trail to satisfy security policies and compliance requirements around AI use.

Key files

What gets installed in your repo

After running the installer, these files form the governance scaffold. Agents read them at the start of every session.

Required

AGENTS.md

The root contract. Defines precedence rules, hard limits, the execution loop, and quality gates. Every agent reads this first.

Required

docs/software-overview.md

Your project's context: product purpose, stack, users, and key behaviors. Agents refuse to start until this is marked ready.

Required

docs/limits.md

Hard boundaries for what agents may never do — prohibited actions, security lines, and branch constraints. Overrides any other instruction.

Optional

~/.config/USER.md

Your personal communication profile. Agents adapt their tone, depth, and framing to match you. Never committed to the repo.

Concepts glossary

AI agent An AI tool that acts autonomously inside a repository — writing code, creating files, or running commands. E.g.: Claude Code, GitHub Copilot, Cursor.
contract An explicit set of rules that defines what an agent can and cannot do in a project. Typically a Markdown file (AGENTS.md) read by the agent at the start of each session.
policy pack A portable collection of contract and configuration files (the AI-Agents project) that can be installed into any repository to provide immediate governance.
session A scoped unit of work — typically mapped to an issue. It has a start, an end, and a handoff file that records what was done.
handoff A document generated at the end of a session that summarizes decisions, changes, and work state. Allows another agent (or human) to resume without losing context.
issue workflow A structured folder and file convention for tracking tasks. Each issue has its own directory with a brief, progress log, and handoff — auditable and platform-independent.
doctor The governancekit doctor command that validates whether a repository's governance scaffold is correct — checks required files, permissions, and configuration.
scope limit An explicit restriction in the contract that prevents the agent from touching files, folders, or systems outside the current session's scope.
start gate The check agents run before any implementation: verify software-overview.md and limits.md are both marked ready. Missing either stops the agent.
work_id A unique identifier for a unit of work, formatted WK-YYYYMMDD-short-slug. Links planning documents and commits to the same traceable task.

Fundamentos

O que é governança de agentes de IA?

Agentes de IA como Claude, Copilot e Cursor escrevem código, tomam decisões e executam ações no seu repositório. São ferramentas poderosas — e sem regras claras, cada agente interpreta o trabalho à sua maneira, sem registro, sem limites de escopo e sem previsibilidade.

Governança de IA é a camada de contratos, limites e registros que garante que agentes (e humanos) sigam os mesmos processos. Em vez de confiar que o agente "entenda" as regras pelo contexto, você as torna explícitas, executáveis e auditáveis.

O resultado: trabalho com IA tão previsível quanto um pipeline de CI — onde qualquer pessoa (ou agente) que entrar no projeto sabe exatamente o que pode, o que não pode, e como documentar o que fez.

Gobernanza de Agentes de IA — conceptos esenciales

Qué significa gobernar agentes de IA, por qué importa y cómo encajan las herramientas de este ecosistema — una guía directa para principiantes.

Fundamentos

¿Qué es la gobernanza de agentes de IA?

Los agentes de IA como Claude, Copilot y Cursor escriben código, toman decisiones y ejecutan acciones en tu repositorio. Son herramientas poderosas — y sin reglas claras, cada agente interpreta el trabajo a su manera, sin registro, sin límites de alcance y sin previsibilidad.

La gobernanza de IA es la capa de contratos, límites y registros que garantiza que los agentes (y las personas) sigan los mismos procesos. En lugar de confiar en que el agente "entienda" las reglas por contexto, las haces explícitas, ejecutables y auditables.

El resultado: trabajo con IA tan predecible como un pipeline de CI — donde cualquier persona (o agente) que entre al proyecto sabe exactamente qué puede hacer, qué no, y cómo documentar lo que hizo.

Audiencia

¿Para quién es esto?

La gobernanza no es solo para equipos grandes. Resuelve problemas reales a cualquier escala.

🧑‍💻

Dev individual

Usas varios agentes de IA en distintos proyectos y quieres que todos sigan las mismas convenciones — sin repetir instrucciones cada vez.

👥

Equipo de desarrollo

El equipo adoptó IA, pero cada miembro configuró su agente de forma distinta. La gobernanza crea un contrato compartido que todos los agentes respetan.

🏢

Ingeniería corporativa

Necesitas trazabilidad, límites de alcance y auditoría para cumplir con las políticas de seguridad y cumplimiento en el uso de IA.
