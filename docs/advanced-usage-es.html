Guía de referencia

Detalles avanzados de uso

Instala, actualiza y configura AI-Agents sin perder contenido del proyecto y entiende cómo se integra la identidad local con AI-GovernanceKit.

Flujo recomendado

# 1a. Instalación nueva
bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.2.1/scripts/install-agents-kit.sh) \
  --target "$PWD"

# 1b. Actualización de una instalación existente
bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.2.1/scripts/install-agents-kit.sh) \
  --target "$PWD" --upgrade

# 2. Configura la identidad de esta máquina/checkout
governancekit configure

# 3. Completa el contexto y los límites; cambia ambas flags a yes
# docs/software-overview.md → project_context_ready: yes
# docs/limits.md            → limits_ready: yes

# 4. Valida y consulta las versiones
governancekit doctor
governancekit --version

No necesitas crear WORKSPACE.md. La identidad de runtime vive en .governancekit-identity.json. Los valores del operador usados en los contratos viven por separado en .credentials/identity.json.

Parámetros de install-agents-kit.sh

ParámetroQué haceCuándo usarlo
--target <dir>Selecciona el proyecto destino; por defecto, el directorio actual.Al ejecutar fuera del proyecto.
--repo <owner/repo>Selecciona otro repositorio de origen.Forks o distribuciones internas.
--ref <ref>Selecciona tag, branch o commit; por defecto v1.2.1.Fijar o probar un origen específico.
--checksum <sha256>Valida el tarball y aborta si el hash no coincide.Instalaciones sensibles y CI.
--upgradeActualiza archivos del kit preservando contexto, reglas, identidad, handoff e issues.Actualización normal.
--forceSobrescribe archivos; incompatible con --upgrade.Solo después de revisar un reemplazo intencional.
--strictCon --upgrade, sale con error si un archivo protegido necesita merge humano.Pipelines de CI.
--checkInforme de solo lectura sobre lo que se reemplazaría o preservaría.Antes de migrar instalaciones antiguas.
--migrateExtrae identidad y separa contenido del proyecto escrito en archivos del kit. Exige TTY y confirmación.Instalaciones heredadas o personalizadas.
--dry-runCon --migrate, informa sin escribir.Auditoría segura y automatización.
--helpMuestra la ayuda incluida en la versión ejecutada.Confirmar opciones disponibles.

--check no se combina con modos de escritura; --dry-run solo se aplica a --migrate; --strict solo se aplica a --upgrade.

Instalación, actualización y migración

Nueva

install-agents-kit.sh --target /proyecto

Crea los archivos ausentes, solicita la identidad y deja los gates de contexto en no.

Actualización

install-agents-kit.sh --target /proyecto --upgrade

Reemplaza solo contenido del kit y reaplica la identidad local.

Heredada

install-agents-kit.sh --target /proyecto --check
install-agents-kit.sh --target /proyecto --migrate
install-agents-kit.sh --target /proyecto --upgrade

Separa el contenido mezclado antes de actualizar.

Parámetros de identidad de GovernanceKit

governancekit configure \
  --operator-name "Nombre" --host-id "maquina-01" \
  --instance-path "/ruta/absoluta/proyecto" \
  --sibling-path "/otro/checkout" \
  --assigned-ports "3000,8000" \
  --branch-ownership "feature/mi-branch"
ParámetroObligatorioSignificado
--operator-nameSíOperador humano de esta instancia.
--host-idSíIdentificador estable de máquina o entorno.
--instance-pathSíRuta absoluta de este checkout.
--sibling-pathNoOtro checkout que puede disputar branches o recursos.
--assigned-portsNoPuertos reservados, separados por coma.
--branch-ownershipNoBranches operadas por esta instancia.
--set KEY=VALUENoCompleta un placeholder heredado; repetible.

Sin flags, governancekit configure pregunta de forma interactiva. Con flags, proporciona los tres campos obligatorios.

Qué preserva una actualización

Territorio del kitTerritorio del proyecto / instancia
AGENTS.md, adaptadores de agentes, .docs/agents/, .docs/workflows/, plantillas y páginas de referencia.docs/software-overview.md, docs/limits.md, docs/, handoff.md, identidades e issues.

Un AGENTS.md modificado se preserva y la nueva versión queda a su lado como AGENTS.md.kit-new para un merge manual.

Códigos de salida

0Operación finalizada.
2Opciones inválidas o incompatibles.
3--migrate ejecutado sin terminal. Usa --migrate --dry-run para previsualizar sin interacción.
4El directorio de destino no existe.
5El destino ya tiene un archivo del kit y no se pasó ni --force ni --upgrade.
6--strict encontró un archivo protegido que requiere merge.
7Checksum de descarga divergente.
8Identidad obligatoria ausente o inválida.
30Archivos instalados, pero contexto o límites aún no están listos.
