Reference guide

Advanced usage details

Install, update, and configure AI-Agents without losing project-owned content, and understand how local identity integrates with AI-GovernanceKit.

Recommended flow

# 1. Install the GovernanceKit CLI — it installs and updates the AI-Agents kit,
#    downloading the pinned release (checksum-verified)
pip install git+https://github.com/EDortta/AI-GovernanceKit.git

# 2a. Fresh install
governancekit --root "$PWD" install-agents

# 2b. Update an existing installation
governancekit --root "$PWD" install-agents --upgrade

# 3. Configure this machine/checkout identity
governancekit configure

# 4. Fill project context and limits, then set both readiness flags to yes
# docs/software-overview.md → project_context_ready: yes
# docs/limits.md            → limits_ready: yes

# 5. Validate and inspect versions
governancekit doctor
governancekit --version

You do not need to create WORKSPACE.md. Runtime instance identity lives in .governancekit-identity.json. Operator contract values live separately in .gk/operator.json.

The local identity files

FilePurposeCreated byGit
.gk/operator.jsonStored answers for the OPERATOR_NAME contract slot (and other operator values); re-applied on every upgrade.governancekit install-agentsIgnored.
.governancekit-identity.jsonMachine and checkout identity: host, path, ports, siblings, and branch ownership.governancekit configureIgnored; mode 0600.
.credentials/identity.jsonLegacy slot-value file written by the retired shell installer; governancekit configure reads it as a legacy source for the operator name — install-agents does not.legacy installsIgnored; mode 0600.

.gk/project-config.json is not identity: it holds the project-configuration answers (scope interview). The doctor may HINT about it when absent.

governancekit install-agents parameters

Fresh install, update, and legacy migration

Fresh

governancekit --root /project install-agents

Creates missing files, collects operator identity, and leaves project readiness gates set to no.

Update

governancekit --root /project install-agents --upgrade

Replaces only kit-owned content and reapplies stored operator values. A hand-edited AGENTS.md is preserved; the new version lands beside it as AGENTS.md.kit-new.

Legacy

governancekit --root /project install-agents \
  --upgrade --migrate-content

Extracts legacy project contracts before upgrading; review what lands in docs/project-rules/.

GovernanceKit identity parameters

governancekit configure \
  --operator-name "Name" --host-id "machine-01" \
  --instance-path "/absolute/project/path" \
  --sibling-path "/other/checkout" \
  --assigned-ports "3000,8000" \
  --branch-ownership "feature/my-branch"
ParameterRequiredMeaning
--operator-nameYesHuman operator for this instance.
--host-idYesStable machine or environment identifier.
--instance-pathYesAbsolute path of this checkout.
--sibling-pathNoAnother checkout that may contend for branches or resources.
--assigned-portsNoComma-separated ports reserved by this instance.
--branch-ownershipNoBranches operated by this instance.
--set KEY=VALUENoFills a legacy placeholder; repeatable.

Without flags, governancekit configure prompts interactively. When flags are used, provide all three required fields.

What an upgrade preserves

Kit territoryProject / instance territory
AGENTS.md, agent adapters, .docs/agents/, .docs/workflows/, templates, and reference pages.docs/software-overview.md, docs/limits.md, docs/, handoff.md, identities, and issues.

A modified AGENTS.md is preserved and the incoming version is written beside it as AGENTS.md.kit-new for a manual merge.

Exit codes

0Operation completed.
1The operation failed — the message names what went wrong (for example a download or checksum failure).
2Invalid or incompatible options, or an unusable target root.

A pending manual merge (AGENTS.md.kit-new) or an operator value that could not be collected is reported in the run's output but still exits 0 — read the output (and run governancekit doctor), do not rely on the exit code alone.
