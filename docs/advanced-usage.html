Reference guide

Advanced usage details

Install, update, and configure AI-Agents without losing project-owned content, and understand how local identity integrates with AI-GovernanceKit.

Recommended flow

# 1a. Fresh install
bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.2.0/scripts/install-agents-kit.sh) \
  --target "$PWD"

# 1b. Update an existing installation
bash <(curl -fsSL https://raw.githubusercontent.com/EDortta/AI-Agents/v1.2.0/scripts/install-agents-kit.sh) \
  --target "$PWD" --upgrade

# 2. Configure this machine/checkout identity
governancekit configure

# 3. Fill project context and limits, then set both readiness flags to yes
# docs/software-overview.md → project_context_ready: yes
# docs/limits.md            → limits_ready: yes

# 4. Validate and inspect versions
governancekit doctor
governancekit --version

You do not need to create WORKSPACE.md. Runtime instance identity lives in .governancekit-identity.json. Operator contract values live separately in .credentials/identity.json.

The two local identity files

FilePurposeCreated byGit
.credentials/identity.jsonValue for the OPERATOR_NAME contract slot.install-agents-kit.shIgnored; mode 0600.
.governancekit-identity.jsonMachine and checkout identity: host, path, ports, siblings, and branch ownership.governancekit configureIgnored; mode 0600.

install-agents-kit.sh parameters

ParameterWhat it doesWhen to use it
--target <dir>Selects the target project; defaults to the current directory.When running outside the project.
--repo <owner/repo>Selects another source repository.Forks or internal distributions.
--ref <ref>Selects a tag, branch, or commit; default is v1.2.0.Pinning or testing a specific source.
--checksum <sha256>Validates the downloaded tarball and aborts on mismatch.Integrity-sensitive installs and CI.
--upgradeUpdates kit-owned files while preserving project context, rules, identity, handoff, and issues.Normal updates.
--forceOverwrites existing files; incompatible with --upgrade.Only after reviewing an intentional full replacement.
--strictWith --upgrade, exits non-zero if a protected file needs a human merge.CI pipelines.
--checkRead-only report of what an upgrade would replace, preserve, or stash.Before migrating an older install.
--migrateExtracts identity and separates project content written into kit files. Requires a TTY and confirmation.Legacy or customized installations.
--dry-runWith --migrate, reports without writing.Safe audits and automation.
--helpShows the help embedded in the running release.Confirming available options.

--check cannot be combined with write modes; --dry-run only applies to --migrate; --strict only applies to --upgrade.

Fresh install, update, and legacy migration

Fresh

install-agents-kit.sh --target /project

Creates missing files, collects operator identity, and leaves project readiness gates set to no.

Update

install-agents-kit.sh --target /project --upgrade

Replaces only kit-owned content and reapplies local identity.

Legacy

install-agents-kit.sh --target /project --check
install-agents-kit.sh --target /project --migrate
install-agents-kit.sh --target /project --upgrade

Separates mixed content before upgrading.

GovernanceKit identity parameters

governancekit configure \
  --operator-name "Name" --host-id "machine-01" \
  --instance-path "/absolute/project/path" \
  --sibling-path "/other/checkout" \
  --assigned-ports "3000,8000" \
  --branch-ownership "feature/my-branch"
ParameterRequiredMeaning
--operator-nameYesHuman operator for this instance.
--host-idYesStable machine or environment identifier.
--instance-pathYesAbsolute path of this checkout.
--sibling-pathNoAnother checkout that may contend for branches or resources.
--assigned-portsNoComma-separated ports reserved by this instance.
--branch-ownershipNoBranches operated by this instance.
--set KEY=VALUENoFills a legacy placeholder; repeatable.

Without flags, governancekit configure prompts interactively. When flags are used, provide all three required fields.

File ownership and exit codes

Kit-owned content includes AGENTS.md, agent adapters, role contracts, workflows, and templates. Project-owned content includes the overview, limits, docs/, handoff, identities, and issues. A modified AGENTS.md is preserved and the incoming version is written as AGENTS.md.kit-new.
